# Задание: перегенерировать фотографии для лендинга TUSAM Group

## Контекст

`/Users/maksimtukmacev/web-projects/t-marketing` — одностраничный лендинг
маркетингового агентства TUSAM Group (React + TypeScript + Vite). Агентство
делает контекстную и таргетированную рекламу, SEO, аналитику, сайты и брендинг.
Оффер лендинга: бесплатный прототип посадочной страницы и бесплатное ведение
первого месяца рекламы, клиент платит только рекламный бюджет.

Дизайн-система — жёсткий швейцарский минимализм: чёрный, белый, два серых и один
кислотно-зелёный акцент `#B0E200`. Спецификация в `design/design.mdc`.

Вёрстка готова, слоты под изображения уже подключены. Нужно **только заменить
файлы картинок**. Код трогать не надо.

## Проблема, которую чиним

В `public/images/` сейчас лежат 14 файлов, сгенерированных по промптам из
`design/prompts/`. Эта библиотека писалась под другой проект — платформу для
креативщиков, — и по смыслу к агентству не подходит:

- карточки кейсов «Производство мебели», «Клиника эстетики», «Строительная
  компания» показывают фэшн-портреты моделей на ярких цветных фонах;
- полоса над блоком кейсов — пустая фотостудия с циклорамой;
- шесть разных ярких фонов в одной сетке спорят между собой и убивают
  зелёный акцент интерфейса.

Картинка должна объяснять блок, рядом с которым стоит.

## Что делать

1. Прочитать `design/IMAGES.md` целиком — это техзадание на съёмку: таблица
   слотов, готовые промпты на каждый кадр, негативный промпт, требования
   к цвету и приёмке.
2. Сгенерировать 14 кадров по промптам из § 6 этого файла.
3. Сложить результат в `public/images/`, **сохранив имена файлов** — они
   прописаны в коде, новый файл просто ложится поверх старого.
4. Проверить себя по чек-листу приёмки (§ 7 в `IMAGES.md`).

## Жёсткие требования

**Пропорции и размеры — точно как в таблице.** Вёрстка режет кадр по
`object-fit: cover`. Если прислать портрет 2:3 в слот полосы 3:1, браузер возьмёт
узкую полоску из середины и растянет её — на этом сломалась первая версия.

| Файл | Пропорция | Размер | Гамма |
|---|---|---|---|
| `hero-band.webp` | 3:1 | 2400×800 | ч/б |
| `cases-band.webp` | 3:1 | 2400×800 | ч/б |
| `texture-paper.webp` | 3:2 | 1800×1200 | приглушённый |
| `honest-workspace.webp` | 1:1 | 1400×1400 | ч/б |
| `case-01-furniture.webp` … `case-06-retail.webp` | 4:5 | 1200×1500 | приглушённый |
| `team-01.webp` … `team-04.webp` | 4:5 | 1200×1500 | ч/б |

**Формат:** WebP, качество 80. Карточки до 150 КБ, полосы до 250 КБ.

**В кадре не должно быть:** текста, букв, цифр, вывесок, логотипов, экранов
с содержимым, дашбордов, графиков и диаграмм. Причины: генератор не умеет
кириллицу, а выдуманная аналитика на сайте реального агентства — это ложная
реклама. Мониторы разворачивать от камеры, ноутбуки закрывать.

**Цвет:** полосы, блок «В чём подвох» и команда — честное ч/б без цветного
каста. Шесть кейсов — единая приглушённая монохромная гамма с холодным
нейтральным тоном, снятые как одна серия: один свет, одно фокусное, один
`--seed`. Кислотный `#B0E200` в фотографиях не использовать.

**Команда:** лица не должны опознаваться — со спины, вполоборота, в контровом
свете или с обрезанной верхней частью кадра. Выдавать сгенерированные лица
за сотрудников нельзя.

## Как проверить результат

```bash
cd /Users/maksimtukmacev/web-projects/t-marketing
npm run dev
```

Открыть страницу и посмотреть на ширинах 1440, 768 и 375:

- кадр каждого кейса читается как ниша клиента, а не как случайный портрет;
- сетка кейсов выглядит одной съёмкой, ни один кадр не «кричит» громче других;
- полосы не съедают экран и не выглядят обрезанными по центру объекта;
- на hover карточки кейса кадр уходит в белое, в левом верхнем углу появляется
  чип категории — он не должен ложиться на важную часть кадра.

## Чего не делать

- Не менять код, разметку и CSS — слоты уже настроены.
- Не менять имена файлов и пропорции.
- Не добавлять цветные фоны из `design/prompts/00-style-core.md`: эта палитра
  относится к другому проекту.
- Не генерировать логотипы клиентов — там сознательные серые заглушки.
